# Icons Menu — notes for Claude Code

macOS menu bar app. Lists every *other* menu bar item in one dropdown and reaches
it through the Accessibility API. Read `README.md` for what it does and why; this
file is for working on it.

## Build and run

```sh
make run       # xcodegen + build + relaunch from .build/
make install   # copy to /Applications and run from there
make probe     # axprobe: the menu bar as the app's own AX layer sees it
make icon      # redraw Resources/AppIcon.icns (only when the artwork changes)
```

`project.yml` is the source of truth. `IconsMenu.xcodeproj` **and**
`Sources/IconsMenu/Info.plist` are both generated by `xcodegen generate` — edit
`project.yml`, never those two, and re-run xcodegen after adding, renaming or
deleting any file.

## Releasing

A release is a tag; the workflow does the rest. **In this order:**

1. Bump `MARKETING_VERSION` in `project.yml`. The tag would override it anyway,
   but local builds should not keep calling themselves the old version.
2. **Update `site/index.html`** — the download button hardcodes the DMG URL
   (`…/releases/download/vX.Y/IconsMenu-X.Y.dmg`), and the version appears in the
   eyebrow line and under the buttons. A tagged release with a stale page points
   everyone at the previous build. This is the step that gets forgotten.
3. Commit, push, then `git tag vX.Y && git push origin vX.Y`.
4. Watch it: `gh run watch <id> -R mx0r/icons-menu`. `.github/workflows/release.yml`
   runs `scripts/build-release.sh` on a macOS runner and publishes the DMG, its
   checksum and the readme to a GitHub release.
5. Verify what shipped rather than assuming: download the DMG, `shasum -c` it,
   mount it, and read `CFBundleShortVersionString` out of the app.

`.github/workflows/pages.yml` publishes `site/` to
<https://mx0r.github.io/icons-menu/> on every push to main that touches it.

Builds are **arm64 only** — the released DMG will not run on an Intel Mac. Set
`ARCHS` in `project.yml` if that ever needs to change.

## Naming

The bundle is `IconsMenu.app` and `PRODUCT_NAME` is `IconsMenu`; that name is load
bearing in the Makefile, the scheme, the release script and `pkill -x`. Everything
a user reads says **Icons Menu**, with a space — menu rows, tooltip, window title,
`CFBundleName`/`CFBundleDisplayName`, DMG readme, release notes, the site.

`NSStatusItem Preferred Position IconsMenu` is a defaults key: renaming it would
forget where the user dragged the icon.

## Facts that cost real debugging — do not re-derive

- **Never touch AX while a menu is on screen.** Every AX call is synchronous IPC
  that pumps the run loop; making one inside `NSMenu`'s tracking loop makes AppKit
  abandon tracking — the dropdown visibly flickers open and shut. The whole tree is
  built from `cachedInventory`, which a background scan keeps warm.
- **`AXUIElementPerformAction` on a menu-opening item does not return until that
  menu closes**, and reports `kAXErrorCannotComplete` (−25204) even though the
  press worked. Never call it on the main thread, and never read its result as
  success.
- **Always set `AXUIElementSetMessagingTimeout`.** Without it a single unresponsive
  process stalls the scan for seconds.
- Control Center reports a **zero-size placeholder child per module you have not
  enabled** — filtered out by size, not by name.
- **Ad-hoc signing revokes the Accessibility grant on every build.** Toggling the
  switch in System Settings does *not* fix it — that re-approves the old signature.
  The entry has to be removed and recreated:
  `tccutil reset Accessibility info.hudak.macos.IconsMenu`, then relaunch and
  re-grant. A real signing identity in `project.yml` would end this.

## Verifying changes

This environment has **no Accessibility or Apple Events permission**: you cannot
drive the menu, click a switch, or screenshot the UI. `osascript` to System Events
returns −1743. Say what you actually verified and what needs the user's eyes —
never claim a UI behaviour works because the code looks right.

What does work headlessly: `make build` (compiles), `plutil -p` on the built
`Info.plist`, `.build/…/axprobe` for the AX layer, `pgrep -x IconsMenu`, and
`defaults read info.hudak.macos.IconsMenu` for what preferences persisted.

## Conventions

- Preferences live in one `Preferences` singleton, not in scattered
  `UserDefaults` reads. Hidden applications are keyed by bundle ID; hidden items by
  `bundleID#index`, which is the only identity most items have.
- The menu is rebuilt from scratch on every open, so preference changes need no
  invalidation — filter during the rebuild.
- Use `trash`, never `rm` — including in scripts and for files you just made.
- Comments explain *why*, not what. If a line looks arbitrary, it is probably load
  bearing: say what breaks without it.
